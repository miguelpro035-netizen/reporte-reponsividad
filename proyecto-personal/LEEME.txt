ACTUALIZACIONES DE LA GUÍA:
- Enfoque Offline-First.
- Cache Storage para recursos estáticos: caché primero.
- HTML: red primero y copia de caché como respaldo.
- Registro del Service Worker dentro de index.html y diagnostico.html.
- Manifest con nombre, icono, start_url, colores, standalone y orientación portrait.
- Indicador visual online/offline.
- Cola local de mensajes de contacto y reintento al recuperar internet.
- Solicitud de Background Sync cuando el navegador lo soporta.

IMPORTANTE:
El proyecto no incluye un servidor/backend ni una URL real para recibir formularios. Para que los mensajes pendientes se envíen automáticamente, configura C.formEndpoint en app.js con un endpoint propio que acepte POST JSON. Sin endpoint, el formulario conserva el comportamiento mailto cuando hay conexión; sin conexión puede guardar el mensaje localmente, pero no enviarlo a un servidor inexistente.

PRUEBA:
1. Abrir la carpeta con Visual Studio Code y Live Server (localhost) o publicarla mediante HTTPS.
2. Cargar una vez con internet para que el Service Worker almacene los recursos.
3. En DevTools > Application > Service Workers comprobar el registro.
4. En DevTools > Network activar Offline y recargar.
5. Volver a Online para comprobar el indicador y el reintento de sincronización.

Cache Storage almacena archivos estáticos; localStorage conserva la cola del formulario. Los archivos deben estar en la misma carpeta.
